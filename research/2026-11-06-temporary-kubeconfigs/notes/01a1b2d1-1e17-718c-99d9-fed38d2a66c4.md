## AWS Secrets Manager Pricing: Two Meters and Worked Examples

AWS Secrets Manager is a fully managed service, and the AWS pricing page keeps the model simple. You pay $0.40 per secret per month, prorated hourly, plus $0.05 per 10,000 API calls. There is no infrastructure to run, no license to buy and no minimum spend. The AWS documentation also states that new customers can receive up to $200 in AWS Free Tier credits, which cover Secrets Manager among other services.

The official examples on the pricing page show where the money goes. An organization with 1,500 secrets and 900,000 API calls a month (1,500 secrets at 20 calls a day for 30 days) pays $600 for storage and $4.50 for calls, a total of $604.50. A larger organization with 10,000 secrets and 12 million calls pays $4,000 for storage and $60 for calls, a total of $4,060. The call meter barely registers. Storage dominates.

Proration helps bursty workloads. AWS prices a secret stored for one hour at roughly $0.00056, which is $0.40 spread across the hours of a 30-day month. Its own example runs 5 million short-lived secrets for an hour at that hourly rate, plus 10 million API calls at $0.05 per 10,000 calls. Teams that mint ephemeral credentials for CI jobs should model that pattern separately from steady-state secrets.

Recent product work has focused on rotation and hygiene rather than price. On October 1, 2026, AWS integrated Secrets Manager with its Recommended Actions framework, so the console surfaces advice on rotation configuration and customer-managed encryption keys at no extra charge. Managed external secrets now cover Jenkins and SonarQube tokens (August 11), Cisco Security Platform and Netskope API keys (August 25), and Databricks and Twilio credentials (October 12).

Encryption keys sit outside the headline bill. Customer-managed keys carry their own billing in the AWS key management service, so a tidy secrets bill can hide a second line item. Developers who want to see how envelope encryption works at the code level can read this walkthrough of [AES-256 encryption in Node.js](https://shattered.io/aes-256-encryption-nodejs/).

AWS Systems Manager Parameter Store is a separate service, not an old name for Secrets Manager. According to an October 2026 comparison, Standard parameters cost nothing and Advanced parameters cost $0.05 per parameter-month. Many teams park low-risk configuration in Parameter Store and reserve Secrets Manager for credentials that need managed rotation.

## HashiCorp Vault and HCP Vault Dedicated: Price, Versions and IBM Ownership

HashiCorp Vault is the reference point for self-managed secrets platforms. It is now an IBM HashiCorp product, still actively developed, and sold as Vault Community Edition, Vault Enterprise and the hosted HCP Vault Dedicated service. Vault 2.2.0 reached general availability on October 15, 2026, and Vault 2.2.1 followed on October 23 alongside maintenance releases 1.21.13 and 1.19.24.

Pricing splits three ways. Community Edition carries no license fee but all the operating cost. Self-managed Vault Enterprise was reported as a custom quote, so any list price you see in a blog post is a guess. HCP Vault Dedicated publishes tiers called Development, Essentials and Standard, with trial, pay-as-you-go and contract-based options. HashiCorp advertises a $500 credit for new pay-as-you-go accounts across the HashiCorp Cloud Platform.

We publish no hourly HCP Vault Dedicated rates here, because the figures reported by a single source could not be matched against HashiCorp’s pricing page, so check that page before you budget. HashiCorp’s tier documentation, last touched October 28, describes Development as a single-node sandbox limited to 25 clients without the HashiCorp Cloud SLA, and Essentials as a highly available production tier with a stated 99.9% SLA.

Operational detail matters as much as price. Beginning with the April 2026 2.x release, Vault Enterprise moved from HashiCorp’s earlier long-term support approach to IBM’s Support Cycle 2 model, so upgrade cadence now follows IBM’s calendar. Vault 2.0.2 and later cap RSA key modulus size at 8,192 bits to address CVE-2026-39829. Vault 2.1.0 changed how PostgreSQL storage authenticates against Azure, checking workload identity before managed identity, and HashiCorp documents that as a breaking change. The Oracle database plugin recently shipped Enterprise version 0.15.1, as the [Oracle plugin release notes](https://developer.hashicorp.com/vault/docs/secrets/databases/oracle/release-notes) show.

HashiCorp’s own October messaging, and the 2.2 release notes as summarized in vendor material, points to a feature push in several areas. Reportedly, Vault Enterprise 2.2 advanced AI identities, PKI automation, post-quantum readiness, Azure AKS Workload Identity, KV v2 secret recovery and Secrets Sync. On October 20, native orchestration for public certificate authority workflows and ACME-based issuance with public CAs was reported as part of 2.2, and a Vault Client on IBM Power was announced in beta on October 22, with general availability planned for a later patch release in 2026. A 2.2.0 release candidate, published October 8, included Enterprise TPM-based authentication for Linux workloads, and HashiCorp stressed that it was not meant for production. If your roadmap depends on any one of these, confirm it against the release notes for the exact patch version you plan to run.

Teams that use encryption-as-a-service features should also pick cipher modes deliberately, and the trade-offs between [AES-GCM and AES-CBC](https://shattered.io/aes-gcm-vs-aes-cbc-2026/) apply there as they do anywhere else. HashiCorp’s October 2026 messaging leans on AI and non-human identities, with Vault 2.2 described as expanding identity-based security for agents, so expect the roadmap to keep tilting that way.

## Azure Key Vault and Google Secret Manager: Cloud-Native Rivals

Azure Key Vault bills by operation, not by secret. Microsoft’s pricing page lists $0.03 per 10,000 transactions for secrets operations, $3 per certificate renewal request, and $1 per key per month for HSM-protected keys (plus $0.03 per 10,000 transactions). Only actively used HSM-protected keys from the prior 30 days are charged, and each version of an HSM key counts separately. Microsoft’s example shows two versions of a 2,048-bit RSA key costing $2 a month, and $10 if they are 3,072-bit keys.

The operational calendar is the bigger Azure story. Control-plane API versions older than 2026-02-01 will stop working on February 27, 2027. Microsoft reportedly advises upgrading to Azure CLI 2.90.0 or later, Az.KeyVault 6.6.1 or later, or Az package 16.3.0 or later well before then. The older Azure Key Vault Secrets Provider extension for Kubernetes is reportedly scheduled for retirement, and Microsoft points users to the Azure Key Vault Secret Store extension. According to the Azure PowerShell release notes, new vaults created with current tooling default to role-based access control.

On the hardware side, Microsoft describes Premium vault keys as protected by FIPS 140-3 Level 3 validated Marvell LiquidSecurity HSMs. External key management for Azure Managed HSM has entered public preview. According to Microsoft’s [Azure SQL Database release notes](https://learn.microsoft.com/en-za/azure/azure-sql/database/doc-changes-updates-release-notes-whats-new?view=azuresql), a public preview now lets transparent data encryption protectors use symmetric AES keys held in Managed HSM. Anyone sizing a broader Microsoft commitment can compare the [AWS and Azure savings plans](https://shattered.io/aws-vs-azure-up-to-72-vs-65-savings-2026/) before locking in.

Google Secret Manager is the hardest to price today. The pages we could fetch confirm it is an active [Google Cloud](https://shattered.io/google-cloud-run-deploy-docker-12-steps-2026/) service, and they reportedly point to a v1 API, a GKE integration that syncs secrets into Kubernetes Secrets, and a rotation guidance update in February 2026. They do not carry a dated price table, so we publish no figure. On October 16, Google Cloud described a Wiz Runtime Sensor add-on for GKE that stores its credentials in Secret Manager through the secret-sync integration. On October 27, Google described an Oracle AI Database capability that resolves database credentials through Secret Manager under Google Cloud IAM policies. Check Google Cloud’s pricing page before you budget.

## OpenBao: HashiCorp Vault Alternatives With No License Fee

OpenBao forked from HashiCorp Vault in late 2023 under the open MPL 2.0 license, according to its own FAQ, and it now ships as a community-governed project under LF Projects, LLC. There is no official list price and no paid plan was confirmed. The cost is the infrastructure and the people who run it. That makes OpenBao one of the most discussed HashiCorp Vault alternatives among platform teams that want to avoid vendor licensing.

The project moves quickly. OpenBao v2.5 added horizontal read scalability, so standby nodes can serve reads. Version 2.6.0 landed on August 18, 2026 with per-namespace sealing, a workflow engine for cross-plugin communication and distroless container images. Namespace sealing gives each tenant separate key material and lets a tenant revoke an instance operator’s access to its own namespace without touching other namespaces. Version 2.7.0 followed on October 5, less than seven weeks later.

Version 2.7 also carries breaking changes. It removed the `file` storage backend, which the project calls unsuitable for production because it lacks high availability and transactions. It also removed the built-in LDAP authentication method, and an issue reports that this hit PostgreSQL users, with a fix intended for a later patch release. OpenBao says v2.8.0 will be a slower release focused on security and stability. A separate open issue, filed between October 27 and 30, reports a reproducible snapshot-save problem with HTTP redirects in the released v2.7.0 CLI. Treat those as upgrade gates, not footnotes.

The upside of v2.7 is a longer feature list than most forks ever manage. Release material reportedly describes PostgreSQL read scalability, external key material, post-quantum algorithms and control-group approvals in this line, along with continued bug-fix work through October on high availability, storage migration, hashing and backend reloading. Those items read like a project closing the gap with the commercial product, and they also show why pinning versions matters, since each minor release has changed something operators touch.

Governance looks healthy for a young project. The OpenBao team describes roughly 15 to 20 active co-maintainers and participation from Adfinis, ControlPlane, GitLab, IOTech, SAP and WALLIX. Michael Hofer, reported as chair of the Technical Steering Committee and CTO of Adfinis, presented the project at Open Source@Siemens 2026, and OpenBao has also spoken at OSSNA 2026 on horizontally scaling secrets management. For migration help, the project publishes a guide on moving from file storage to PebbleDB on Kubernetes. Teams on v2.6 or earlier who used file storage should read the [OpenBao PebbleDB migration guide](https://openbao.org/docs/next/guides/migrations/k8s-pebbledb/) before they touch v2.7.

## Infisical: Per-Identity Pricing After a $40M Series B

Infisical prices by identity, which flips the cost curve compared with AWS. The Free plan costs $0 a month for up to five identities and includes the dashboard, CLI, SDKs, Kubernetes Operator, agent, integrations, secret scanning and community Slack support. Pro costs $18 per identity per month and adds secret versioning, point-in-time recovery, role-based access controls, rotation, temporary access provisioning, SAML SSO, IP allowlisting and 90-day audit log retention. Top-tier capabilities include dynamic secrets, dedicated infrastructure, SCIM, LDAP, approval workflows, KMIP, KMS and HSM support, audit log streaming, custom roles and a 99.99% SLA.

Infisical’s cloud plans are named Free, Pro, Advanced and Enterprise in its rate-limit documentation. Limits vary by plan, and the [Infisical rate limit reference](https://infisical.com/docs/api-reference/overview/rate-limits) shows figures such as 200 reads per minute and 90 writes per minute in the limits it displays. That detail matters for CI-heavy shops, because a flat per-identity price does not remove throttling.

The business is scaling fast. On October 27, 2026, Infisical announced a $40 million Series B, presented in its own announcement rather than in an independently verified filing. Infisical’s CEO is Vlad Matsiiako. The core product is MIT-licensed, and both self-hosted and cloud options exist.

Agent Vault deserves a flag. Infisical describes it as an AI-agent security product, in an article dated October 22 to 24, 2026, so treat it as new and unproven. Do not plan a production rollout around it until you have tested it yourself. The pitch is credible, though: handing raw environment files to AI coding agents is a liability.

```
def aws(secrets, calls): return secrets * 0.40 + calls / 10_000 * 0.05 def azure_ops(calls): return calls / 10_000 * 0.03 def infisical_pro(identities): return identities * 18 print(aws(1_500, 900_000)) # 604.5 print(azure_ops(900_000)) # 2.7 print(infisical_pro(25)) # 450
```

The shape tells the story. AWS cost tracks the number of secrets you store, and splitting one credential into per-environment copies multiplies the bill. Infisical cost tracks the number of humans and machines that read secrets, so a large catalog read by few identities is cheap. Azure’s operations meter is small enough that its real cost sits in HSM keys and engineering time. Self-run tools, Vault Community and OpenBao, carry a $0 license line and a nonzero staffing line. If three engineers each spend a fraction of their month on upgrades, backups, unsealing and on-call, you have bought a very expensive free tool, or a sensible one, depending on your scale and your tolerance for risk.

HCP Vault Dedicated sits between those poles. The Essentials tier is billed per cluster-hour plus a per-client fee, so HCP makes sense when the alternative is a dedicated platform engineer, and less sense for a 15-secret startup. Serverless teams should also model call volume honestly, since a function that fetches a secret on every invocation can turn the quiet call meter into a visible one. The comparison of [AWS Lambda, Azure Functions and Cloud Run](https://shattered.io/aws-lambda-vs-azure-functions-vs-cloud-run-2026/) helps size invocation counts, and caching a secret for the life of an execution environment cuts calls sharply.

### How to Model Your Own Bill

A five-step method turns the tables above into a number you can defend in a budget meeting.

1. Count secrets per environment, and multiply by the number of environments that really hold a copy.
2. Count distinct readers, meaning services, pipelines, people and agents that fetch values.
3. Sample call volume for a week from application logs, then scale to a month.
4. Price each candidate on its own meter, using the worked scenarios above as a template.
5. Add a staffing line for self-run tools, and a migration line for any tool that needs new integrations.

Run the model twice, once with today’s counts and once with counts doubled. Secrets sprawl tends to double faster than headcount, and a tool that looks cheap at 500 secrets can look different at 5,000.

## Seven Real-World Deployments From 2026

Vendor feature lists read better than they operate. Seven documented cases from recent months show what each tool does in production.

* **Jenkins and SonarQube on AWS (August 11, 2026).** AWS added managed external secrets for Jenkins API tokens and SonarQube tokens, including token replacement and revocation workflows. A CI team that used to rotate those tokens by hand now lets Secrets Manager do it.
* **Databricks and Twilio rotation (October 12, 2026).** Managed external secrets for both services rotate credentials automatically without customer-maintained rotation Lambda functions, which removes a whole class of glue code from data pipelines and messaging apps.
* **Wiz Runtime Sensor on GKE (October 16, 2026).** Google Cloud described an add-on that uses the GKE Secret Manager secret-sync integration to keep Wiz credentials outside the cluster and restrict access through a dedicated service account.
* **Oracle AI Database on Google Cloud (October 27, 2026).** Google described a capability that resolves database credentials through Secret Manager and enforces Google Cloud IAM policies, so the database never holds a static password in a config file.
* **Azure SQL with Managed HSM (public preview).** Microsoft is previewing support for symmetric AES keys held in Azure Key Vault Managed HSM as transparent data encryption protectors, a pattern aimed at regulated workloads that need hardware-backed keys.
* **OpenBao at Siemens (2026 talk).** A July 27 post from the OpenBao project summarizes a talk at Open Source@Siemens 2026 on sustainable secrets management, evidence that large industrial firms are evaluating the fork alongside SAP and GitLab, which both participate in the project.
* **The Nx npm incident (August 2025).** Infisical’s blog cites the case where a malicious npm package version ran coding agents with safety checks turned off. The lesson for secrets management is blunt: any credential sitting in a readable `.env` file is within reach of a compromised dependency or a misled agent.

The pattern across all seven is the same. Secrets stores are moving from static storage toward brokering, where a service rotates, scopes and revokes credentials on behalf of tools, pipelines and now agents. Pick the product that covers the integrations you already run.

## Hidden Costs and Common Mistakes

Headline rates leave out the costs that surprise teams in month three. Most of them come from design choices, not vendor pricing.

* **Per-environment duplication.** On AWS, a database password copied into dev, staging and production counts as three secrets. At $0.40 each, a catalog of 500 logical credentials across four environments is billed once per copy, so the monthly cost is a multiple of what the credential count alone suggests.
* **Chatty clients.** Fetching a secret on every request, not once at startup, inflates the call meter. On AWS the meter is cheap, but throttling and latency arrive first.
* **Config stored as secrets.** Feature flags and endpoint URLs belong in a parameter store or config service. Reserve the secrets tool for values that need rotation and audit.
* **Customer-managed keys.** Encrypting secrets with your own keys adds key service billing and key policy work on top of the secrets bill.
* **Self-run labor.** Vault Community and OpenBao have no license fee, but unsealing, backups, upgrades, auditing and on-call rotations all cost engineer time. OpenBao’s removal of file storage in v2.7 shows how a routine upgrade can turn into a storage migration.
* **API deadlines.** Azure’s February 27, 2027 cutoff for older control-plane API versions will break automation that pins an old version. Scripts, Terraform providers and CI images all need checking.
* **Contract terms.** HCP Vault Dedicated offers trial, pay-as-you-go and contract-based options, and self-managed Enterprise has no published price, so negotiate with a usage forecast in hand and ask how client counts are measured.
* **Confusing keys with secrets.** A key management service protects cryptographic keys, while a secrets manager stores and rotates credentials such as database passwords and API tokens. Buying one does not replace the other.

A short audit before any migration saves money: count secrets by environment, count readers, and log call volume for a week.

## Use-Case Recommendations: Which Tool Fits Which Team

Match the tool to the constraint that hurts most, not to the feature list.

1. **AWS-only shop with up to a few thousand secrets.** Use AWS Secrets Manager. The pricing is predictable, rotation is managed, and recent integrations cover Jenkins, SonarQube, Databricks, Twilio, Cisco and Netskope. At 1,500 secrets you pay $604.50 a month.
2. **Azure-first regulated workloads.** Use Azure Key Vault Premium or Managed HSM when auditors want hardware-backed keys. Plan for the February 27, 2027 API cutoff and for the reported retirement of the older Kubernetes secrets provider extension.
3. **Google Cloud-first teams on GKE.** Use Google Secret Manager with the GKE secret-sync integration, and get a dated price from Google before you budget, since the sources we could fetch carried none.
4. **Hybrid or multi-cloud enterprises that need dynamic secrets and PKI.** Use HashiCorp Vault. HCP Vault Dedicated fits teams without a platform group, and self-managed Enterprise fits teams that already run stateful services well. Vault 2.2 is the current line.
5. **Platform teams with SRE capacity and a licensing allergy.** Use OpenBao, but pin versions deliberately and read each release’s removals before upgrading. Check its feature parity with the Vault features you actually use.
6. **Startups and developer-experience-driven teams.** Use Infisical. The Free plan covers five identities at $0, and Pro at $18 per identity wins when each identity reads dozens of secrets.
7. **Container-heavy teams.** Pair the secrets tool with the platform that runs your workloads. The comparison of [Fargate, Cloud Run and Container Apps](https://shattered.io/fargate-vs-cloud-run-vs-container-apps-2026/) shows how each runtime handles identity, which determines how cleanly workloads authenticate to a vault. Teams that also weigh managed edge security can look at the [Cloudflare, AWS and Azure WAF](https://shattered.io/cloudflare-vs-aws-vs-azure-waf-6-releases-20-days-2026/) comparison for the same vendor-alignment question.

## Migration Guide: Moving Secrets Without Downtime

Most migrations fail on inventory, not on tooling. Work in this order.

1. Inventory every secret, owner and reader. Export names only, never values.
2. Classify each secret by blast radius and rotation need.
3. Pick the target and stand up a non-production instance. For OpenBao, confirm your storage backend is supported on the target version.
4. Wrap secret reads in one internal library, so applications call a single function, not a vendor SDK.
5. Dual-read for a window. The app tries the new store first and falls back to the old one, with a metric on every fallback.
6. Migrate values with a script that reads from stdin or a protected file, never from shell arguments that land in history or process lists.
7. Rotate every migrated secret once the new store is authoritative, because the old copies existed in a different trust boundary.
8. Revoke old access, delete old secrets after a retention hold, and update runbooks.

For AWS Secrets Manager to Vault or OpenBao, a loop like this moves values into a KV mount. The `bao` binary is OpenBao’s CLI. Replace it with `vault` for HashiCorp Vault.

```
aws secretsmanager list-secrets \ --query 'SecretList[].Name' --output text \ | tr '\t' '\n' > secret-names.txt while read -r name do value=$(aws secretsmanager get-secret-value \ --secret-id "$name" --query SecretString --output text) printf '%s' "$value" | bao kv put -mount=secret "$name" value=- done < secret-names.txt
```

For Azure Key Vault as the source or target, upgrade your tooling first. Microsoft advises Azure CLI 2.90.0 or later, Az.KeyVault 6.6.1 or later, or Az package 16.3.0 or later ahead of the February 27, 2027 API cutoff.

```
az --version az upgrade az keyvault secret set --vault-name my-vault --name db-password --value "$value"
```

Azure secret names allow letters, numbers and dashes, so map AWS-style path names such as `prod/db/password` to a flat form like `prod-db-password` and keep a mapping file. For Infisical, the dashboard and CLI import paths accept environment files, which suits teams leaving raw `.env` files behind. Test each import in a staging project first, since identity-based pricing means a quick count of who and what will read the new store.

### Rollback Plan

Keep the old store read-only and intact until every consumer has run on the new store through at least one full rotation cycle. Write down the exact condition that triggers a rollback, such as an error rate above an agreed threshold on secret fetches, and name the person who can call it. Test the rollback on staging before production, because the first time you try to flip readers back should not be during an incident. Snapshot the new store before each cutover step, and store the unseal or recovery material for self-run tools in two separate places with documented access.

If you run OpenBao on file storage, plan the PebbleDB move before v2.7. The migration guide covers Kubernetes, and the same principle applies elsewhere: stop writes, snapshot, migrate, verify seal status, then resume.

## Verdict: Which Secrets Manager Wins on Price and Fit

There is no single winner, but the numbers give a clear decision rule. AWS bills $0.40 per secret and Infisical Pro bills $18 per identity, so the two cross at 45 secrets per identity ($18 divided by $0.40). Below that ratio, AWS Secrets Manager is cheaper on license cost. Above it, Infisical Pro is cheaper. At 1,500 secrets and 25 identities the ratio is 60, which is why Infisical Pro lands at $450 against AWS at $604.50.

For most AWS-only teams, AWS Secrets Manager remains the safe default because the bill is predictable and the service needs no staff. For hybrid enterprises that need dynamic secrets, PKI and policy depth, HashiCorp Vault 2.2.1 is the strongest platform, with HCP Vault Dedicated as the way to buy it without a platform team. Essentials is billed per cluster-hour plus a per-client fee, so HCP pays off when you need Vault capabilities, not when you only need storage. For ops-capable teams that want zero licensing, OpenBao v2.7.0 is viable if you accept its breaking changes. Azure Key Vault wins inside Azure when HSM-backed keys matter. Google Secret Manager fits GKE-heavy teams once Google publishes a price you can verify.

Four dates will reshape this picture soon. Microsoft Ignite runs November 17 to 20, 2026, a likely venue for Azure security news. OpenBao v2.8.0 is expected to be a quieter, stability-focused release. Vault’s 2.2 line will keep collecting patch releases, with the IBM Power client due to reach general availability in a later patch. And Azure’s February 27, 2027 API cutoff will force action from any team that has not upgraded tooling. Google Secret Manager buyers should watch for a dated price they can verify, because it remains the one gap in this comparison.

Our pick for new projects with no strong cloud lock-in is Infisical for small teams and Vault for large ones, with AWS Secrets Manager as the cost-conscious default whenever everything already runs on AWS. ## FAQ: Secrets Manager Pricing and Alternatives

### How much does AWS Secrets Manager cost per month?

AWS charges $0.40 per secret per month, prorated hourly, plus $0.05 per 10,000 API calls. There is no minimum fee, setup fee or long-term commitment. AWS’s own examples put 15 secrets at about $6 a month and 1,500 secrets with 900,000 calls at $604.50.

### Is HashiCorp Vault free?

Vault Community Edition carries no license fee, but you operate it yourself. Self-managed Vault Enterprise has no published price, and HCP Vault Dedicated sells Development, Essentials and Standard tiers with trial, pay-as-you-go and contract options. Check HashiCorp’s pricing page for current HCP rates.

### Is OpenBao a drop-in replacement for Vault?

OpenBao forked from Vault in late 2023, but it is not frozen in place. Version 2.7 removed the file storage backend and the built-in LDAP authentication method, so test every feature you depend on before switching and read each release announcement for removals.

### Is Azure Key Vault cheaper than AWS Secrets Manager?

On the operations meter, yes. Azure lists $0.03 per 10,000 secrets operations against AWS’s $0.05 per 10,000 calls, and the verified Azure pages show no per-secret storage fee. Azure charges $1 per month for each actively used HSM-protected key, so total cost depends on what you store.

### What does Google Secret Manager cost?

The Google pages we could fetch on October 30, 2026 did not carry a dated price table, so we publish no figure. Check Google Cloud’s official pricing page before you budget, and confirm any third-party number against it.

### When does Infisical beat AWS Secrets Manager on price?

Infisical Pro costs $18 per identity per month and AWS costs $0.40 per secret per month, so Infisical is cheaper once you store more than 45 secrets per identity that reads them. Teams with five or fewer identities can use the Free plan at $0.

### What happens to Azure Key Vault on February 27, 2027?

Control-plane API versions older than 2026-02-01 stop working on that date. Microsoft advises upgrading Azure CLI, the Az.KeyVault module and the Az package to current versions before then. Azure Key Vault itself is not being retired.

### Should I use Parameter Store instead of Secrets Manager?

For low-risk configuration, often yes, because Parameter Store is a separate and cheaper AWS service. For credentials that need managed rotation, Secrets Manager earns its $0.40 per secret.
