# Kubernetes MCP Servers Compared: kubectl, EKS, Argo CD

A Kubernetes MCP server lets an AI assistant such as Claude Code, Cursor or VS Code work with Kubernetes through tools instead of you pasting kubectl output. The servers differ in the level they work at: some speak to the Kubernetes API, one to Argo CD, and some to a delivery platform. That level decides what the assistant can see, what it can break and which credentials it holds.

## Three levels of Kubernetes MCP server

Every server on this list implements the [Model Context Protocol](/blogs/what-is-an-mcp-server), so any MCP client can call it. What differs is what sits behind the tools.

## The five servers side by side

Checked against each project’s README or vendor page on 16 October 2026. Flags and tool names change between releases, so confirm against the current README before you rely on one.

| SeaGit MCP server | Platform (applications and deployments) | Hosted at seagit.com/mcp | SeaGit API key with scopes | Redeploy and promote, both flagged for approval |

## containers/kubernetes-mcp-server

A Go server that talks to the Kubernetes API directly rather than wrapping kubectl or Helm, from the containers community on GitHub. It ships as a native binary, an npm package, a Python package and a container image. Its `--read-only` flag blocks create, update and delete, and `--disable-destructive` narrows writes when read-only is off. Pair it with a service account that has only the permissions you want the assistant to have, not cluster-admin.

`--read-only`
`--disable-destructive`

## Flux159/mcp-server-kubernetes

A Node.js server, started with npx, that exposes kubectl and Helm as tools: get, describe, logs, apply, scale, rollout, Helm install and upgrade, and port forwarding. Setting `ALLOW_ONLY_NON_DESTRUCTIVE_TOOLS=true` removes the delete and uninstall tools while keeping reads and creates. It uses whichever context your kubeconfig points at, so check the context before asking it to change anything.

`ALLOW_ONLY_NON_DESTRUCTIVE_TOOLS=true`

## Amazon EKS MCP server

AWS publishes an open-source EKS MCP server and, since 21 November 2025, a fully managed version in preview that AWS hosts, so there is nothing to install. It authenticates with AWS IAM, records calls in CloudTrail, and covers cluster creation, application deployment and troubleshooting with AWS guidance built in. It is the natural choice if your team works directly with EKS and IAM; it is EKS-only.

## Argo CD MCP server

The Argo CD server, developed in the argoproj-labs GitHub organization, connects an assistant to the Argo CD API. Its tools create, update, delete and sync Argo CD applications and run resource actions. It runs over stdio or as an HTTP service that takes the Argo CD URL and token in headers. If your team already deploys through Argo CD, it keeps the assistant inside that workflow.

## SeaGit MCP server

SeaGit’s server is hosted at `seagit.com/mcp` and works at the platform level: organizations, environments, clusters, applications, their instances in each environment, and deployments, including preview deployments and the main (production) one. Ten tools cover listing all of those, reading deployment logs, redeploying, and promoting a preview to main.

`seagit.com/mcp`

It authenticates with a SeaGit API key, so every call is checked against the key’s scopes and the account’s policies and recorded in the audit log, the same as the REST API. Redeploy and promote are annotated as write tools and promote as destructive, so clients ask before running them. It needs a paid plan, because API keys do. The setup is in the [MCP server docs](/docs/mcp-server), and [this walkthrough](/blogs/deploy-kubernetes-from-claude-code) uses it from Claude Code.
